# Weekly Report Writing Guide

## Purpose

This guide defines how to write the data team's weekly report. The weekly report is the team's primary recurring communication. It should be scannable in 2 minutes, comprehensive enough to replace ad-hoc questions, and structured so readers can find what they need without reading the whole thing.

## Core Principles

1. **Consistent structure**: Same format every week so readers know where to look
2. **Scannable**: Headlines and bold text tell the story; body text adds detail
3. **Complete**: Cover all active workstreams so nothing falls through the cracks
4. **Forward-looking**: Do not just report what happened; flag what is coming
5. **Honest**: Report setbacks and blockers with the same prominence as wins

## Report Structure

### Header
- Report title: "Data Squad Weekly — [Start Date] to [End Date]"
- Author and distribution list
- Reading time estimate

### Section 1: This Week in One Paragraph
- 3-5 sentences summarizing the most important findings, decisions, and changes
- Written for someone who will only read this section
- Include the single most important number of the week

### Section 2: Key Metrics Snapshot
- Table of 5-8 core metrics with current value, prior period, trend direction, and status
- Use consistent formatting: green/yellow/red or up/down/flat indicators
- Link each metric to its dashboard for drill-down

| Metric | This Week | Prior Week | Change | Status |
|---|---|---|---|---|
| Weekly Active Users | 45,200 | 44,100 | +2.5% | On track |
| 7-Day Retention | 38% | 41% | -3pp | Needs attention |
| MRR | $1.24M | $1.22M | +1.6% | On track |

### Section 3: Findings and Insights
- 2-4 findings from the week, each structured as:
  - **Headline**: One sentence stating the finding
  - **Detail**: 2-3 sentences with supporting data
  - **Implication**: What this means for the business
  - **Action**: What we recommend or what is already in progress

### Section 4: Experiment Status
- Table of active experiments with status, days running, and early signals
- Results for any experiments that concluded this week
- Upcoming experiment launches

### Section 5: Data Team Operations
- Pipeline health: any incidents, delays, or known issues
- New dashboards, reports, or tools shipped
- Ongoing projects and their progress
- Blockers and requests for help

### Section 6: Looking Ahead
- What the data team is focused on next week
- Upcoming deadlines or deliverables
- Questions the team is investigating
- Any scheduled maintenance or changes that will affect data availability

## Writing Standards

- Write in present tense for current state, past tense for completed work
- Use active voice: "We found" not "It was found"
- Bold key numbers and metric names
- Keep each section independent; readers should be able to skip sections
- Total length: 1-2 pages maximum (excluding the metrics table)
- Send by Monday at 10 AM to set the week's context

## Distribution and Feedback

- Post in #data-updates with a one-line summary and link to the full report
- Send directly to key stakeholders (heads of product, engineering, CS, growth)
- Invite feedback: "Reply in thread with questions or topics for next week"
- Archive reports in a consistent, searchable location

## Common Mistakes

- Writing a different structure every week, forcing readers to relearn the format
- Including too much detail in the main report instead of linking to deeper analyses
- Reporting only positive findings and downplaying issues
- Missing the send deadline, reducing the report's relevance
- Not including the metrics snapshot, making it hard to track trends week over week
- Writing the report for the data team instead of for the report's audience
