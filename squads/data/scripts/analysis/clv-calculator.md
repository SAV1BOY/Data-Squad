# clv-calculator

## Purpose

Calculates Customer Lifetime Value (CLV) using both historical (actual observed revenue) and simple predictive methods (projected future value). Supports segmentation by acquisition channel, plan type, and cohort. Provides per-user CLV scores and segment-level summaries for use in marketing ROI, retention prioritization, and financial forecasting.

## When to Run

- **Scheduled**: Weekly on Sundays at 05:00 UTC.
- **Triggered**: After significant pricing changes or new revenue model launches.
- **Ad-hoc**: For financial planning, investor reporting, or acquisition budget decisions.

## Inputs

| Input | Source | Description |
|---|---|---|
| `analytics.transactions` | Data warehouse | Transaction records: user_id, amount, transaction_date, type |
| `analytics.users` | Data warehouse | User attributes: signup_date, acquisition_channel, plan_type |
| `analytics.cohort_user_map` | Data warehouse | Cohort assignments from cohort-builder |
| Parameters | CLI args | time_horizon_months, discount_rate, segments |

### Parameters

| Parameter | Type | Default | Description |
|---|---|---|---|
| `time_horizon_months` | int | 24 | Projection horizon for predictive CLV |
| `annual_discount_rate` | float | 0.10 | Discount rate for NPV calculation |
| `segments` | list[string] | `["acquisition_channel"]` | Dimensions to segment CLV |
| `min_tenure_days` | int | 30 | Minimum user age to include in prediction training |

## Process

### Step 1: Compute historical CLV per user

Sum of all revenue generated by each user since acquisition.

```sql
CREATE OR REPLACE TABLE analytics.clv_historical AS
SELECT
    u.user_id,
    u.signup_date,
    u.acquisition_channel,
    u.plan_type,
    DATEDIFF('month', u.signup_date, CURRENT_DATE) AS tenure_months,
    COUNT(t.transaction_id) AS total_transactions,
    SUM(t.amount) AS total_revenue,
    AVG(t.amount) AS avg_transaction_value,
    MIN(t.transaction_date) AS first_transaction_date,
    MAX(t.transaction_date) AS last_transaction_date,
    DATEDIFF('day', MAX(t.transaction_date), CURRENT_DATE) AS days_since_last_transaction
FROM analytics.users u
LEFT JOIN analytics.transactions t ON u.user_id = t.user_id AND t.type = 'purchase'
GROUP BY u.user_id, u.signup_date, u.acquisition_channel, u.plan_type;
```

### Step 2: Compute purchase frequency and monetary metrics

These feed the predictive model.

```sql
CREATE TEMPORARY TABLE user_rfm AS
SELECT
    user_id,
    tenure_months,
    total_transactions,
    -- Frequency: transactions per month
    CASE WHEN tenure_months > 0
         THEN total_transactions::FLOAT / tenure_months
         ELSE total_transactions END AS monthly_frequency,
    avg_transaction_value,
    total_revenue,
    days_since_last_transaction,
    -- Alive probability proxy: recency relative to tenure
    CASE WHEN tenure_months > 0
         THEN 1.0 - LEAST(days_since_last_transaction::FLOAT / (tenure_months * 30), 1.0)
         ELSE 1.0 END AS alive_probability
FROM analytics.clv_historical
WHERE tenure_months >= :min_tenure_days / 30;
```

### Step 3: Simple predictive CLV (frequency-based projection)

Using the formula:
**Predicted CLV = (Avg Monthly Revenue) x (Projected Remaining Lifetime Months) x (Alive Probability) x (Discount Factor)**

Where the discount factor for monthly revenue at annual rate `r` is:
**Discount Factor = (1 - (1 + r/12)^(-T)) / (r/12)**

```sql
CREATE OR REPLACE TABLE analytics.clv_predicted AS
SELECT
    user_id,
    tenure_months,
    monthly_frequency,
    avg_transaction_value,
    alive_probability,

    -- Monthly revenue estimate
    monthly_frequency * avg_transaction_value AS est_monthly_revenue,

    -- Projected remaining months
    GREATEST(:time_horizon_months - tenure_months, 0) AS remaining_months,

    -- Discount factor (present value of annuity)
    CASE WHEN :annual_discount_rate > 0
         THEN (1 - POWER(1 + :annual_discount_rate / 12,
                         -1 * GREATEST(:time_horizon_months - tenure_months, 0)))
              / (:annual_discount_rate / 12)
         ELSE GREATEST(:time_horizon_months - tenure_months, 0)
    END AS discount_factor,

    -- Predictive CLV (future value only)
    (monthly_frequency * avg_transaction_value)
        * alive_probability
        * CASE WHEN :annual_discount_rate > 0
               THEN (1 - POWER(1 + :annual_discount_rate / 12,
                               -1 * GREATEST(:time_horizon_months - tenure_months, 0)))
                    / (:annual_discount_rate / 12)
               ELSE GREATEST(:time_horizon_months - tenure_months, 0)
          END AS predicted_future_clv,

    -- Total CLV = historical + predicted future
    total_revenue + (monthly_frequency * avg_transaction_value)
        * alive_probability
        * CASE WHEN :annual_discount_rate > 0
               THEN (1 - POWER(1 + :annual_discount_rate / 12,
                               -1 * GREATEST(:time_horizon_months - tenure_months, 0)))
                    / (:annual_discount_rate / 12)
               ELSE GREATEST(:time_horizon_months - tenure_months, 0)
          END AS total_clv

FROM user_rfm;
```

### Step 4: Segment-level CLV summary

```sql
CREATE OR REPLACE TABLE analytics.clv_by_segment AS
SELECT
    u.acquisition_channel AS segment_value,
    'acquisition_channel' AS segment_dimension,
    COUNT(*) AS user_count,
    AVG(p.total_clv) AS avg_clv,
    MEDIAN(p.total_clv) AS median_clv,
    PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY p.total_clv) AS p75_clv,
    PERCENTILE_CONT(0.90) WITHIN GROUP (ORDER BY p.total_clv) AS p90_clv,
    SUM(p.total_clv) AS total_clv_pool,
    AVG(p.alive_probability) AS avg_alive_probability,
    AVG(h.total_revenue) AS avg_historical_revenue,
    AVG(p.predicted_future_clv) AS avg_predicted_future_revenue
FROM analytics.clv_predicted p
JOIN analytics.clv_historical h ON p.user_id = h.user_id
JOIN analytics.users u ON p.user_id = u.user_id
GROUP BY u.acquisition_channel;
```

### Step 5: Cohort-level CLV

```sql
CREATE OR REPLACE TABLE analytics.clv_by_cohort AS
SELECT
    c.cohort_date,
    COUNT(*) AS cohort_size,
    AVG(p.total_clv) AS avg_clv,
    SUM(h.total_revenue) AS realized_revenue,
    SUM(p.predicted_future_clv) AS projected_future_revenue,
    AVG(p.alive_probability) AS avg_alive_rate
FROM analytics.clv_predicted p
JOIN analytics.clv_historical h ON p.user_id = h.user_id
JOIN analytics.cohort_user_map c ON p.user_id = c.user_id
GROUP BY c.cohort_date
ORDER BY c.cohort_date;
```

### Step 6: CLV tier assignment

```python
percentiles = query("SELECT PERCENTILE_CONT(0.25), PERCENTILE_CONT(0.50), PERCENTILE_CONT(0.75) FROM analytics.clv_predicted")

update_query = """
    UPDATE analytics.clv_predicted SET clv_tier = CASE
        WHEN total_clv >= {p75} THEN 'platinum'
        WHEN total_clv >= {p50} THEN 'gold'
        WHEN total_clv >= {p25} THEN 'silver'
        ELSE 'bronze'
    END
""".format(p75=percentiles.p75, p50=percentiles.p50, p25=percentiles.p25)
```

| Job log | `analytics.job_log` | Run metadata with aggregate CLV statistics |

## Error Handling

| Error | Action |
|---|---|
| No transactions for a user | Set historical CLV to 0, alive_probability to 0, predicted CLV to 0 |
| User with negative total_revenue (refunds exceed purchases) | Cap at 0 for CLV calculation, flag for finance review |
| Tenure of 0 months (brand new users) | Exclude from prediction training set, assign avg CLV of their segment |
| Discount rate produces extreme values | Clamp discount factor between 0 and time_horizon_months |
| Missing acquisition_channel | Group into "unknown" segment, log count of unattributed users |
