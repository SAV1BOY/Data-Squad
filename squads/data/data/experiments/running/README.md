# Running Experiments

This subdirectory contains documentation for experiments currently in progress.

## Purpose

Active experiments need accessible, up-to-date documentation so the team can monitor progress, check interim results (without making premature decisions), and coordinate any operational requirements.

## What Goes Here

- Full experiment design documents with locked analysis plans
- Pre-registration documents specifying the analysis approach before results are observed
- Interim monitoring notes (sample size accumulation, data quality checks)
- Operational notes about any issues encountered during the experiment
- Stakeholder communication updates

## Conventions

- Name files with the experiment ID: `EXP-002-weekly-digest-email.md`
- The design document should be finalized and locked before the experiment starts
- Record the actual start date and expected end date prominently at the top
- Do not make ship/kill decisions based on interim data unless a pre-specified stopping rule is met
- Move the file to `completed/` when the experiment ends and the analysis is finalized
- All running experiments must respect the 14-day minimum duration (DEC-003)
